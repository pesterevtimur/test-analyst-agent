# Эталонный набор

Тридцать вопросов, по которым измеряется качество агента. Один вопрос, один файл.

## Что где лежит

```
evals/
  dataset/open/      20 вопросов, видны в работе
  dataset/sealed/    10 вопросов, открываются один раз перед сдачей
  expected/          замороженные ответы эталонных запросов
  reports/           отчёты прогонов
  src/               контракты, сравнение результатов
  tests/             проверки самого набора, без базы и без модели
  tools/             заморозка эталонных ответов
```

## Устройство набора

| Ось | Разложение |
|---|---|
| Сложность | простые 10, средние 13, сложные 7 |
| Доступность | рабочие 20, запечатанные 10 |
| Вид ответа | ответ 24, отказ 6 |

Шесть ловушек, где правильный ответ отказ: персональные данные, вопрос вне данных, неоднозначная формулировка (две), отсутствие данных за период, отсутствие плана в витрине.

Каждый вопрос называет ловушки семантического слоя, в которые он ведёт. Тест `test_documented_traps_of_the_semantic_layer_are_exercised` проверяет обратное направление: ни одна критическая ловушка словаря не осталась без вопроса.

## Как сравнивается ответ

По результату выполнения, не по тексту запроса (ADR-001):

- порядок строк не важен;
- лишние колонки не ошибка;
- числа сходятся с относительным допуском 0,5%;
- лишняя строка это ошибка (ADR-007);
- повтор ключа это ошибка: так выглядит задвоенное соединение.

## Смещение и чем оно смягчено

Набор написал автор агента. Это смещение, и оно названо прямо.

1. Вопросы и эталонный SQL написаны и закоммичены до того, как появился промпт агента. Порядок виден в истории git и не переписывается задним числом.
2. Запечатанное подмножество прогоняется один раз перед сдачей. Разрыв точности между рабочими и запечатанными вопросами и есть мера подгонки.
3. Формулировки взяты из языка бизнеса и мок-интервью, а не из семантического слоя. Тест `test_questions_are_written_in_business_language` запрещает имена таблиц и полей в тексте вопроса.
4. Место под десять вопросов заказчика оставлено: файл кладётся в `dataset/open/`, ничего перестраивать не нужно.

## Запуск

Быстрые проверки, без базы и без модели, идут в CI на каждый push:

```
docker run --rm -v "$PWD:/w" -w /w \
    -e PYTHONPATH=/w/mcp_server/src:/w/evals/src \
    sap-agent-mcp:dev python -m pytest evals/tests -q
```

Заморозка эталонных ответов, нужна поднятая реплика:

```
set -a && . ./.env && set +a
docker run --rm --network host --user "$(id -u):$(id -g)" \
    -v "$PWD:/w" -w /w \
    -e PYTHONPATH=/w/mcp_server/src:/w/evals/src \
    -e ORACLE_APP_USER -e ORACLE_APP_USER_PASSWORD \
    -e ORACLE_DSN=127.0.0.1:1521/REPPDB1 \
    sap-agent-mcp:dev python evals/tools/freeze_gold.py
```

Ключ `--check` ничего не выполняет и говорит, какие замороженные ответы отстали от своих запросов.

## Почему ответы заморожены, а не считаются на лету

Замороженный ответ хранит отпечаток запроса, который его получил. Правка запроса делает ответ несвежим, и тест это ловит. Обновление реплики двигает числа, и это видно как изменение файла, которое кто-то обязан посмотреть, а не как новая правда, приехавшая молча.
