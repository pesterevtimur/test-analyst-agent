# CLAUDE.md, проект sap-agent

Контракт агента. Прочитай целиком до первого действия.

Коротко: содержание работы задаёт `BRIEF.md`, дальше `SPEC.md`. Этот файл задаёт способ работы.

## 1. Что за проект

Тестовое задание для Русала: агент-аналитик над данными Oracle и SAP. Аналитик получает вопрос от бизнеса, агент ускоряет каждый шаг обработки (поиск таблиц, сборка SQL, проверка результата, оформление ответа). Доступ к данным идёт через MCP-сервер, только на чтение, с ограничителями.

Заказчик тестового: Михаил. Исполнитель со стороны Тимура: этот агент. Срок сдачи 8 сентября 2026.

Полный контекст в `BRIEF.md`. Когда появится `SPEC.md`, он становится источником истины по содержанию, а бриф остаётся историей решений.

## 2. Роли

Архитектурные решения принимает Тимур. Ты исполнитель. Спорный вопрос выносится ему, а не решается молча.

Тимур ведёт проект через агентов и не проверяет факты интуицией. Поэтому цена непроверенного утверждения здесь выше обычного: оно проходит дальше без фильтра.

## 3. Закон проекта

Семь правил. Нарушение любого требует явного согласия Тимура в переписке.

1. **`SPEC.md` источник истины.** Любое отклонение от спецификации сначала оформляется как ADR в `docs/adr/` (контекст, решение, альтернативы, последствия) и только потом реализуется.
2. **Один агент, одна задача.** Контракты между компонентами типизированы через pydantic и проверяются тестами.
3. **Ничего не объявляется готовым без свежей проверки в том же ходе.** Это скилл `evidence-before-action`, он же покрывает отправку сообщений, публикацию и запись факта. «Тесты проходят» без прогона тестов в этом же ходе есть враньё, а не экономия.
4. **Skill не пишется руками.** Только через `skill-creator` (плагин). Если скилл что-то запрещает, поверх применяется `harness/meta-skills/skill-creator/addenda/pressure-testing.md`: три и более сценария давления, RED, GREEN, REFACTOR, и только потом `metadata.pressure-tested: "yes"`.
5. **Wiki-страница не пишется руками.** Содержимое `wikis/` создаётся скиллами `wiki-llm-builder`, `wiki-ingest`, либо возвращается из `wiki-query`.
6. **Факт без citation не существует.** Каждое фактическое утверждение в wiki несёт маркер `^[src:<source-id>:<locator>]`. `wiki-lint` это проверяет.
7. **Таблица не пересказывается, а хранится как данные.** Таблица из источника уходит в `wikis/<domain>/data/tables/<slug>.csv` с метаданными рядом. Пересказ таблицы прозой есть ошибка линтера.

Правила 4, 5, 6, 7 пришли из личного харнесса Тимура (`pesterevtimur/super-agentic-ops`). Правила 1, 2 и раздел про язык пришли из брифа. Правило 3 общее для обоих.

## 4. Язык

Документация проекта на русском: без англицизмов там, где есть русское слово, без длинного тире, без корпоративной воды, вывод первым.

Код, имена, комментарии, сообщения коммитов на английском.

Скиллы в `.claude/skills/` и их addenda на английском. Это осознанное исключение: они живут рядом с англоязычным апстримом, сравниваются с ним построчно при перепиновке, и переводить их значит терять эту возможность.

## 5. Свежие документы вместо памяти

Знания модели отстают от этих проектов, они меняются быстрее. Перед установкой и настройкой читай документацию через веб:

- OpenClaw: docs.openclaw.ai
- Langfuse self-hosting: langfuse.com/self-hosting
- Образ Oracle: github.com/gvenzl/oci-oracle-free
- Схемы-примеры: github.com/oracle-samples/db-sample-schemas
- Спека Agent Skills: agentskills.io/specification

Прочитанное не остаётся в контексте одной сессии: оно уходит в `wikis/` через `wiki-ingest` с citations. Так требование брифа «читай свежее» становится проверяемым, а не декларацией.

## 6. Безопасность и границы

- Все порты сервисов привязаны к `127.0.0.1`. Наружу не торчит ничего.
- Секреты только в `.env`. В git попадает только `.env.example`.
- Не трогай `ufw`, `sshd`, пользователей, ключи, настройки Claude Code и Telegram-канала. Исключение делает Тимур явно и разово (так 2 сентября 2026 были поставлены плагины `superpowers` и `skill-creator`).
- Доступ агента к данным только на чтение, отдельный пользователь Oracle с правом SELECT на схему SH.

## 7. Ресурсы сервера

Ubuntu 26.04, 4 vCPU, 7.6 ГБ памяти, 75 ГБ диска. Стоят: docker 29.1.3, compose v2, bun 1.4, git, Claude Code 2.1.258. Нет: node, gh, pip, venv, psql.

После каждого поднятия сервисов проверяй `free -h` и `df -h` и сообщай числа. Если памяти не хватает, порядок такой: сначала лимиты памяти в compose, потом замена Langfuse на Arize Phoenix, потом вопрос Тимуру.

## 8. Git

Коммиты маленькие, по одному законченному шагу, сообщения на английском. Ничего не удаляй и не переписывай массово без вопроса. В конце дня коммит с тегом `day-N`.

## 9. Отчёты

Тимуру пишешь коротко и по делу: что сделано, что не получилось, что нужно от него. Он читает с телефона через Telegram, длинные простыни туда не влезают. Числа и пути конкретные, оценки без воды.

## 10. Структура репозитория

```
sap-agent/
  BRIEF.md              исходный бриф, история решений
  SPEC.md               источник истины по содержанию
  CLAUDE.md             этот файл
  README.md             запуск за 10 минут
  log.md                дневник проекта, читать в начале сессии
  docs/                 requirements, limits, verification, process, not-done, demo, adr/
  infra/                compose, init-скрипты Oracle, конфиги Langfuse
  mcp_server/           сервер и семантический слой (semantic/*.yaml)
  agent/                конфигурация OpenClaw, системная инструкция
  control_panel/        панель управления
  evals/                эталонный набор, тесты, отчёты
  .github/workflows/    CI
  .claude/skills/       скиллы проекта
  harness/              харнесс: архитектура, глоссарий, пины апстрима, инструменты
  wikis/                домены знаний, память проекта
```

Каталоги из `docs/` и ниже по списку заводятся на этапе 0 брифа, а не заранее.

## 11. Порядок чтения

Не загружай всё подряд:

1. Всегда: этот файл.
2. В начале сессии: `log.md`, чтобы узнать, на чём остановились.
3. Перед работой над задачей: `BRIEF.md` (раздел под задачу), затем `SPEC.md`.
4. Если задача архитектурная или про контракты линтера: `harness/architecture.md`.
5. Если задача про создание или правку скилла: `skill-creator` подхватится сам, addendum лежит в `harness/meta-skills/skill-creator/addenda/`.
6. Если задача внутри конкретной wiki: локальный `wikis/<domain>/CLAUDE.md`.

## 12. Чего не делаешь

- Не пишешь `SKILL.md` руками.
- Не правишь `wikis/<domain>/` напрямую и не трогаешь `raw/` ни при каких обстоятельствах.
- Не отвечаешь по теме, у которой есть wiki, не заглянув в неё.
- Не заявляешь о готовности без свежей проверки.
- Не даёшь агенту данных инструментов сверх четырёх из брифа: ни shell, ни файлов, ни веба.
- Не используешь векторные базы и embedding-поиск, пока хватает markdown и grep.
- Не копируешь чужие скиллы без аудита и адаптации.
